# 报名订单在线收款

入口：运营平台 → 招生报名 → 报名订单 → 未支付 / 部分支付订单右侧「收款」。

页面显示应收、已付和剩余金额。开通易宝后点击「生成收银台」，可打开收银台、复制付款链接，或让付款人扫码进入易宝收银台。二维码编码的是易宝收银台链接；实际可用的微信、支付宝、银行卡等方式取决于商户签约产品。

付款成功后，后端验证易宝通知并更新支付流水、报名订单，前端自动刷新。付清订单进入待入班状态，工作人员可办理入班。仅浏览器返回成功页不会将订单标记为已支付。

## 目前能用到哪一步

已完成前端入口、后端易宝下单调用、收银台链接持久化、余额补缴、只读付款返回页和回调校验。当前本机未开通易宝商户、未配置商户应用和密钥，支付开关关闭，页面会显示「在线支付尚未开通」。不会自动生成假二维码或假到账记录。

自动化测试中使用测试渠道替身验证成功、失败、重复通知、并发和事务行为。这不等于已验证易宝实际下单、扣款、SDK 真实签名或公网通知。

## 第一次接支付需要准备什么

1. 向易宝申请商户入网及聚合收银台产品权限，取得商户号和 YOP 应用。先申请测试 / 沙箱接入信息；是否提供沙箱及其支付能力，以易宝实际开通结果为准。
2. 按易宝开放平台要求生成应用密钥，登记商户应用公钥，取得平台验签公钥或官方 SDK 配置。商户号、应用 ID、密钥和环境必须属于同一套接入信息。
3. 准备可由易宝访问的公网回调域名，将通知路径转发到 Java 服务。开发期可以使用自己控制的 HTTPS 隧道；localhost / 127.0.0.1 无法接收易宝通知。
4. 配置后先在获准测试的环境用独立小额订单验证下单、支付、通知和订单结果，再切换正式环境。

没有商户资料时可以演示订单、支付流水及页面流程，无法执行易宝真实扣款。申请资料通常需要商户主体信息，具体要求由易宝审核。

## Java 配置

Java 项目 docs/yop_sdk_config.example.json 是结构示例，仅包含占位符。优先使用易宝提供的实际 SDK 配置，并按其要求配置证书；不要直接把示例当作有效商户配置。

把真实配置放在代码仓库外，例如 /absolute/path/to/yop_sdk_config.json。Java 启动前设置：

```powershell
$env:YQ_YEEPAY_MERCHANT_NO = '自己的收款商户号'
$env:YQ_YEEPAY_PARENT_MERCHANT_NO = '自己的接入商编'
$env:YQ_YEEPAY_SDK_CONFIG_FILE = '/absolute/path/to/yop_sdk_config.json'
```

接入商编为空时使用收款商户号，是否允许这种模式取决于商户签约。Spring Boot 读取 yq.yeepay.sdk-config-file，SDK 使用该外置配置；更换配置文件或环境变量后需重启 Java。无需修改前端代码，也不要把商户私钥写入前端环境变量。

在运营端「系统配置」设置以下已有配置项：

| 配置键 | 值 |
| --- | --- |
| yeepayEnabled | true |
| yeepayUseSandbox | 测试环境为 true，正式环境为 false；与实际商户信息对应 |
| yeepayNotifyUrl | https://自己的回调域名/yq-admin/yop-callback/paySuccess |
| yeepayReturnUrl | http://127.0.0.1:5173/payment/return（同机测试），线上替换为前端公网地址 |
| yeepayExpireMinutes | 1—120，示例值 30 |
| yeepayLimitPayType | 根据易宝签约产品填写；不限制时留空 |

系统配置约 10 秒缓存。付款人使用手机或其他设备时，返回页也必须使用可访问的前端公网域名；域名对应的反向代理应正确支持前端路由和后端 API。建议正式环境统一使用 HTTPS。

存量数据库执行 Java 项目 src/main/resources/sql/add_payment_checkout.sql，新增字段和收款权限。当前本地库已执行并验证可重复运行。本机 scripts/init-local.cjs 也会自动加载该脚本。具备订单新增 / 编辑按钮权限的角色会获得收款权限，已有登录会话需刷新权限或重新登录。

## 链路及接口

- GET /api/payments/orders/{id}/checkout：查询金额、配置状态及当前支付记录；需要管理员签名和收款权限。
- POST /api/payments/orders/{id}/checkout：服务端计算余额、生成随机支付单号并调用易宝统一下单；同一有效收银台复用。
- /payment/return?orderId=...&paymentOrderNo=...：公开付款返回页面。
- GET /student-api/public/orders/{id}/checkout-status：只读查询，不返回姓名、手机号、商户配置、收银台链接、JWT 或签名密钥。
- /yq-admin/yop-callback/paySuccess：由易宝 SDK 接收支付通知，显式检查签名、商户、渠道单号、支付单号和订单金额。重复成功仅记账一次，后到失败不会覆盖成功；状态和金额在同一事务更新。

原学生端支付入口复用同一收银台服务。旧的公开 payment-return-status 接口也改为只读，不再凭支付单号发放学员登录态；学员应通过学生登录接口登录。

## 异常处理与当前限制

渠道请求超时可能表示「已建单但响应未收到」，因此保留待确认支付单并阻止重复下单。收银台过期也不会被当作渠道已经关单。当前查询读取已收到通知的本地结果，尚未接入渠道主动查单、渠道关单、退款或自动对账任务。

遇到「待确认」先到易宝商户后台核对或等待可靠通知。不能仅通过改数据库状态清除待确认记录后重新收款；应根据渠道实际结果实施后续核实流程。已有待确认支付时，报名订单禁止编辑或删除。

现有 LOCAL_DEMO / LOCAL_FIXTURE 流水继续作为演示样本，不代表实际扣款。请创建独立测试订单，不要对演示学员批量发起真实收款。
