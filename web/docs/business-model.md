# 职业培训与就业服务业务说明

本次改造以职业技能培训机构为服务对象。课程商品负责销售定价，课程体系负责教学内容，两者使用现有数据模型分别管理。

## 业务边界

- 招生报名：维护课程商品和报名订单，接收支付结果。
- 教学履约：完成学员入班，安排培训班级、师资、课表、值班和作业考核。
- 学员档案：记录学员基础信息、报名商品、所属班级及学习权益。
- 就业服务：管理求职简历、录音转写、AI 面试复盘及面试题库。不包含岗位招聘、企业入驻、Offer 或就业率统计。
- AI 支撑：知识库、数据分析、招生宣传内容生成；模型任务由 Python 服务执行。

## 支付与履约状态

支付状态沿用 UNPAID、PARTIAL_PAID、PAID、CLOSED。

履约状态由 Java 查询订单与学员档案时计算，不额外维护一个容易失步的状态字段：

| 履约状态 | 含义 |
| --- | --- |
| PENDING_PAYMENT | 订单尚未支付完成 |
| PENDING_ENROLLMENT | 已支付，尚未找到与订单商品、手机号、班级一致的学员档案 |
| ENROLLED | 已支付，且学员档案与订单一致；线下培训还需班级一致 |
| CLOSED | 订单已关闭 |

GET /api/sales/orders 支持 fulfillmentStatus 筛选，并返回 studentId 与 fulfillmentStatus。

POST /api/sales/orders/{id}/enrollment 接收 phone、password、graduationSession、school、education、joinTime，可选 classId；班级以订单为准，禁止跨班提交。

入班操作使用事务及订单行锁，校验已支付金额、手机号、班级和已有档案。管理端与学员端复用同一业务服务。已收款或已关闭订单不能直接编辑或删除，避免破坏报名和履约关联。

## 权限与迁移

导航分组调整不改变既有菜单编码。没有可访问子菜单的分组隐藏；工作台只请求当前账号有权访问的业务模块。

新增 button:order:enroll 与 order:enroll 权限。迁移脚本给具有订单编辑权限的岗位补充办理入班权限，其他岗位可由管理员按需分配。超级管理员沿用已有角色规则。

JWT、HMAC 签名和接口权限拦截器恢复注册；修复管理端 API 权限路径与部署 context-path 的匹配。员工和学员响应不序列化密码。
